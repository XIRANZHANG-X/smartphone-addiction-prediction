## 设计原则

**关键路径只放一个人。其余 8 人每人独占一个文件，任何人交不出来，删掉他的文件，主线毫发无伤。**

这不是不信任，是工程上的必要设计。10 人项目最常见的死法是"某个人卡住了，后面所有人都动不了"。我们从结构上消除这种可能：

- 所有人共享同一份 `folds.rds` 和 `features_raw.rds`，接口固定
- 每人只写自己的 `R/06_model_<你的名字>.R`，**不动别人的文件**
- 集成脚本自动扫描目录，加模型不需要改任何已有代码
- 因此 10 个人可以同时 `push` 到 `main`，不需要开分支，不会冲突

**关于 L3 的重要更新**：我们原本判断"约束插补是全项目的核心创新，跑出来的 AUC 提升就是我们区别于其他组的地方"。**实测推翻了这个判断**——在 xgboost 上它比什么都不做还差。

但 L3 依然不可放弃，理由变了：它在 **glmnet 上是决定性最优**（比中位数高 0.0107，p<0.0001），而正是"同一个方法在两类模型上方向相反"这个反差，构成了本项目最有价值的发现。**L3 现在是核心发现的一半，另一半是 L1。**

## 每个人具体要交什么

### A / B / C / D —— 四条建模线

**你要做的**：复制 `R/06_model_TEMPLATE.R`，改名成 `R/06_model_L<你的线号>_<模型名>.R`，填入你那条线的插补方法和模型。

**你的线是什么**：

| 代号 | 插补方法 | 要跑的模型 | 还差哪些 |
|---|---|---|---|
| A | 不插补，直接喂 NaN | xgboost、lightgbm | **lightgbm** |
| B | 中位数/众数填补 | glmnet、ranger、xgboost、lightgbm | **ranger、lightgbm** |
| C | 约束条件插补（见项目说明第五节） | glmnet、ranger、xgboost、lightgbm | **ranger、lightgbm** |
| D | missRanger PMM 单次随机插补 | glmnet、ranger、xgboost、lightgbm | **glmnet、ranger、lightgbm** |

`06_model_L1_xgboost.R` / `L2_xgboost` / `L2_glmnet` / `L3_xgboost` / `L3_glmnet` / `L4_xgboost` 这六个文件已经写好并跑通，可以直接拿来改——把 `MODEL_NAME` 和「模型区」的 `fit_predict` 换成你要跑的模型即可，框架区一个字都不用动。

**验收标准**（四条全部满足才算完成）：

1. 产出 `output/oof/oof_grid_<名字>.rds`，长度正好 **200,000**
2. 脚本从头跑到尾无报错，且**重跑两次结果完全一致**（seed 固定）
3. 插补在**折内**拟合——模板里的循环结构不要动
4. 在 `submissions/log.csv` 里登记你的 CV AUC 和跨折标准差

**不要做的事**：不要改 `folds.rds`，不要改 `03_features.R`，不要改别人的文件。有需求找组长。

### E —— EDA 与可视化

### F —— 特征消融 + 可解释性

**消融实验**：逐个去掉特征组，看 AUC 掉多少。要回答的问题：

- 去掉 `stress_level` + `academic_work_impact` + `notifications_per_day`（我们判定的噪声）——AUC 是不是几乎不动？
- 去掉缺失指示特征——AUC 是不是几乎不动？（验证发现 6；已完成，结论为「不动」，该组特征据此删除）
- 只保留 `屏幕时间`、`周末屏幕时间`、`社交时间` 三个特征——能到多少 AUC？

**可解释性**：跑特征重要性（xgboost 自带的，或 SHAP），看模型认为什么重要，和我们的 EDA 结论是否一致。不一致的地方特别值得讲。

产出 `reports/ablation.qmd`。

## 常见问题

**Q：我跑出来的 AUC 比别人低很多，是不是我做错了？**
先检查两件事：(1) 你有没有用共享的 `folds.rds`；(2) 插补是不是写在折内。如果 AUC 异常地**高**，更要警惕——多半是泄漏。

**Q：我可以加特征吗？**
可以，但加在你自己的文件里，不要改 `03_features.R`。如果你的新特征效果好，告诉组长，由组长决定是否升级到共享层。

**Q：我的电脑跑不动怎么办？**
所有对比实验都在 20 万行的子集上跑，普通笔记本可以承受。如果 ranger 还是太慢，减少树的数量并在 log 里注明。

**Q：我改了别人的文件怎么办？**
`git checkout -- <文件路径>` 撤销。如果已经 push 了，联系组长。
