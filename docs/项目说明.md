# 项目说明

本文档面向组员、助教与任何第一次接触本项目的人。读完这一篇，你应该能回答：这个任务是什么、数据长什么样、我们为什么这么做、以及怎么把结果跑出来。

---

## 一、任务是什么

预测一个人是否**手机成瘾**（`addicted_label`，0 或 1）。

这是一个二分类问题，但提交的**不是 0/1 标签，而是概率**。评价指标是 **ROC-AUC**（ROC 曲线下面积）。

### 为什么是 AUC 而不是准确率

数据里 70.94% 的人被标为成瘾。如果无脑全预测"成瘾"，准确率就有 70.94%——看起来不低，但这个模型毫无用处。

AUC 衡量的是**排序能力**：任取一个成瘾者和一个非成瘾者，模型给成瘾者打的分更高的概率。全预测同一个值时 AUC = 0.5，等于瞎猜。所以 AUC 不会被类别不平衡糊弄。

这也解释了为什么官方给的 `sample_submission.csv` 里所有行都填 `0.7094243450313797`——那正好是训练集的成瘾比例，代表"什么都不知道"的基线，AUC = 0.5。

### 提交格式

```
id,addicted_label
691369,0.83
691370,0.12
...
```

## 三、我们发现了什么

以下结论全部来自**全量扫描**（691,369 行全跑，不是抽样），可用 `R/02_eda.R` 复现。

### 发现 1：一条 100% 成立的硬约束 ★

```
每日屏幕时间 >= 社交媒体时间 + 游戏时间
在 451,246 行（三列都不缺的全部行）中成立 451,246 次 = 100.00%
```

这不是统计相关，是**结构性约束**。含义很直观：屏幕时间由社交、游戏、以及其他用途（浏览器、视频、办公……）组成。

我们把剩下那部分叫 `other_screen = 屏幕时间 − 社交 − 游戏`，均值 3.71 小时，标准差 1.94。

这条约束曾是我们整个方法的立足点（第五节）。不过后来实测发现，它在插补中**只对 0.06% 的行起作用**——这个落空本身也成了一个发现，见第六节。

### 发现 2：周末屏幕时间是一个冗余代理

`周末屏幕时间 / 每日屏幕时间` 的比值稳定在 **1.33** 左右（标准差 0.50），两列相关系数 **+0.80**。

而且这两列很少同时缺失。所以**一列缺了可以用另一列重建**。

### 发现 3：特征之间的相关结构

```
屏幕时间 ↔ 周末屏幕   +0.80          屏幕时间 ↔ 社交    +0.60
屏幕时间 ↔ 工作学习   +0.53          屏幕时间 ↔ 游戏    +0.43
社交     ↔ 游戏      +0.09   ← 两个近乎独立的分量
年龄 / 通知数 / 应用打开次数 / 睡眠  ↔  一切  ≈ 0
```

### 发现 4：三个类别特征是纯噪声（已被消融实验验证）

`stress_level`（压力水平）、`academic_work_impact`（是否影响学业）、`gender`（性别）**完全不携带信息**。把数据按屏幕时间分段后，前两者的 6 种组合下成瘾率完全平坦：

| 组合 | 低分段 | 中分段 |
|---|---|---|
| High / No | 0.2035 | 0.6685 |
| High / Yes | 0.2085 | 0.6678 |
| Low / No | 0.2073 | 0.6735 |
| Low / Yes | 0.2133 | 0.6665 |
| Medium / No | 0.2162 | 0.6809 |
| Medium / Yes | 0.2201 | 0.6712 |

波动幅度小于 0.02，纯属随机。

**消融实验证实了这一点**：把这三个特征全部删掉，xgboost 的 AUC 变化 **+0.00009（p=0.183，不显著）**——它们确实一点用都没有。

这是一个反直觉的结果：**"压力大"和"影响学业"听起来明明和成瘾高度相关，但在这份数据里它们什么都不是。**

> ### ⚠️ 一个我们犯过并已修正的错误
>
> 本节的早期版本还把 `notifications_per_day`（通知数）也列为"同样平坦"的噪声。**这个判断是错的**，而且错得离谱——消融实验显示，单独删掉这一个特征，AUC 掉 **0.00721**（p<0.0001，5/5 折同号），**是全项目所有方法差异中最大的一个**。`app_opens_per_day` 同理，独自值 0.00624。
>
> 错误的根源是**只看了边际分布**。详见下面的发现 9——它和发现 7 的 Simpson 悖论其实是同一个教训的两副面孔。

### 发现 5：标签几乎是确定的

在 `daily_screen_time_hours` 不缺失的行上（占全量 86.1%），按 1 小时分箱：

```
 0: 0.242    4: 0.313    8: 0.912    12: 0.9997
 1: 0.242    5: 0.403    9: 0.989    13: 0.9996
 2: 0.229    6: 0.570   10: 0.998
 3: 0.289    7: 0.757   11: 0.9995
```

极差 0.771，13 个间隔中 3 处下降（0→1、1→2、12→13，最大一次 0.006）。

**数据完整时，这道题几乎没有难度。** 难度全部来自缺失。

> **对照检验**：把标签随机打乱后重复完全相同的分箱，
> 极差从 0.771 塌到 0.024，13 个间隔里 7 处下降 ——
> 同一变量、同一分箱，换个标签就没有单调性。
>
> **本节此前的口径已更正。** 早期版本用的是 `屏幕时间 + 社交时间`
> （0.138 → 1.000），并曾被质疑"两个时长相加、右端必然到 100%"。
> 该构造已从项目中整体移除（理由见 6.5）。改用单变量之后，
> **没有任何一个分箱是零阴性的**：最高箱 2,659 个样本中仍有 1 个阴性，
> 此前显示的"1.000"确系四舍五入所致。
> 完整核查见 `R/15_fig2_audit.R`。

### 发现 6：缺失是完全随机的（MCAR），缺失指示无用

在 Kaggle 竞赛里有个常用套路：给每一列加一个"这里缺失了吗"的 0/1 特征，因为缺失本身往往携带信息（比如收入高的人不填收入）。

**这个套路在本题无效。** 我们逐列比较了"缺失时的成瘾率"和"不缺失时的成瘾率"，12 列的差值全部小于 0.0042；按缺失个数分组，成瘾率在 0.696–0.719 之间毫无趋势。

缺失是人为随机注入的（MCAR，Missing Completely At Random）。

> 这是一个**阴性结论**——我们试了，它没用。但阴性结论同样有价值：它告诉我们信息不在"哪里缺失"里，而只能从"没缺的部分"去推断"缺了的部分"。这直接决定了后面的方法选择。

> **后续处置**：正因为它们是诊断变量而非预测变量，这 13 列（12 个 `is_na_*` 加 `n_missing`）已于消融验证后从特征集中移除，特征数由 31 减为 17。详见 6.5。复现该项检验需先执行 `WITH_NA_INDICATORS <- TRUE; FORCE_REBUILD <- TRUE; source("R/03_features.R")`。

### 发现 7：工作学习时间的 Simpson 悖论

单独看 `work_study_hours`，工作学习时间越长，成瘾率越高（0.611 → 0.749 → 0.930）。这很反直觉——难道学习越多越容易手机成瘾？

但只要控制住屏幕时间，方向立刻反转：在每日屏幕时间低于 4.5 小时的人群里（占 15.3%），工作学习时间越长，成瘾率越**低**（0.299 → 0.044）。

原因是 `屏幕时间 ↔ 工作学习` 相关 +0.53。边际上看到的正相关，完全是屏幕时间这个混淆变量制造的假象。

**这是 Simpson 悖论的一个干净实例**，也提醒我们：单变量分析会骗人。

### 发现 8：「空闲时间」假设不成立

我们猜测过 `24 − 睡眠 − 工作 − 屏幕` 可能是一个有意义的"空闲时间"。实测均值 7.19、标准差 3.78，但有 **1.84% 为负数**——说明它不是硬约束，只能当作一个软特征使用。

### 发现 9：两个"看起来是噪声"的特征，其实是除屏幕时间外最重要的 ★

这是我们**自己推翻自己**得到的发现，也是全项目最实用的一条教训。

我们最初把 `notifications_per_day`（通知数）和 `app_opens_per_day`（应用打开次数）判为噪声，依据是它们的**边际分箱曲线又平又跳**：

```
notifications 每 50 一箱：  0.727  0.694  0.727  0.703  0.704
app_opens 每 30 一箱：      0.607  0.761  0.633  0.707  0.724  0.761
```

看不出任何规律。但消融实验给出了完全相反的结论：

| 单独删掉这一个特征 | AUC 变化 | p |
|---|---|---|
| `notifications_per_day` | **−0.00721** | <0.0001 |
| `app_opens_per_day` | **−0.00624** | <0.0001 |
| `stress_level` + `academic_work_impact` + `gender`（三个一起删） | +0.00009 | 0.183 |
| 全部 12 个缺失指示 + `n_missing` | −0.00006 | 0.598 |
| `age` | −0.00008 | 0.330 |

**作为对照**：整个项目里四条插补线之间的最大差距（L1 对 L4）也只有 0.00292。**这两个"噪声"特征各自的价值，是我们全部插补研究成果的两倍以上。**

#### 为什么边际分析会看走眼：天花板效应

按 `daily_screen_time_hours` 的五分位把人分成五段，段内再看这两个特征：

| 屏幕时间段 | notifications 的效应 | app_opens 的效应 |
|---|---|---|
| 最低 20% | 0.312 → 0.234（极差 0.078） | 0.277 → 0.316（极差 0.046） |
| 次低 | 0.487 → 0.401（极差 0.086） | 0.446 → 0.530（极差 0.086） |
| 中间 | 0.823 → 0.746（极差 0.077） | 0.779 → 0.838（极差 0.059） |
| 次高 | 0.986 → 0.980（极差 **0.006**） | 0.982 → 0.988（极差 **0.005**） |
| 最高 20% | 0.999 → 0.999（极差 **0.000**） | 0.999 → 0.999（极差 **0.000**） |

两个特征在**标签尚未饱和的低 60%** 区间里都有干净的效应；而在高 40% 区间里，屏幕时间已经把所有人推到 0.98–1.00，**任何其他变量都不可能再移动什么**。

做边际分析时，我们把有效的 60% 和完全无效的 40% 平均在了一起，真实信号被稀释到看不见。

#### 而且两者方向相反

- **通知数越多，越不容易成瘾**（负向）
- **应用打开次数越多，越容易成瘾**（正向）

在聚合统计里，这两个相反的效应进一步互相抵消，把边际曲线压得更平。

这个方向差异本身就值得讲：**通知是被推给你的（被动接收），打开应用是你自己发起的（主动使用）。主动使用预测成瘾；被动接收不预测，甚至标记出那些懒得理会手机的人。**

#### 与发现 7 的关系

发现 7（`work_study_hours` 的 Simpson 悖论）和本发现是**同一个教训的两副面孔**：

| | 边际看到的 | 条件下的真相 | 掩盖机制 |
|---|---|---|---|
| 发现 7 | 正相关 | 负相关 | 混淆变量（屏幕时间） |
| 发现 9 | 无相关 | 有明确相关 | 天花板效应 + 方向抵消 |

> **在这份数据里，任何基于单变量边际分析的结论都不可信。** 我们在发现 7 里写下了这条教训，然后在发现 4 里立刻违反了它。这不是修辞——是真实发生的过程，也是我们保留这段记录的原因。

## 四、所以这道题的本质是什么

把发现 5 和发现 6 放在一起看：

- 数据完整时，标签几乎确定（发现 5）
- 缺失完全随机，缺失位置不含信息（发现 6）
- 但 61% 的行有缺失

**结论：这不是建模题，是缺失数据题。**

理论上最优的预测是"在给定观测到的那部分特征的条件下，标签的期望值"。这需要对缺失的分量做**条件边缘化**——通俗说就是：我没看到你的社交媒体时长，但我看到了你的屏幕时间和游戏时间，我能推断出你社交媒体时长大概是多少，进而推断你是否成瘾。

而发现 3 告诉我们，特征之间相关性高达 0.4–0.8，**观测到的特征里藏着大量关于缺失特征的信息**。

三种常见做法的差别就在这里：

| 做法 | 我们开工前的判断 |
|---|---|
| 用均值/中位数填补 | 把所有缺失值填成同一个数，应该会破坏信号 |
| 让 XGBoost 原生处理 NaN | 只是让缺失样本走一个专门分支，没利用特征间的相关结构，应该不够好 |
| **利用相关结构 + 硬约束去插补** | ← 我们赌这个最好 |

> **剧透**：这三个判断里，第一个和第三个都错了。第二个看起来最笨的做法，反而在梯度提升树上是最好的。为什么，见第六节。

## 五、我们的假设：约束条件插补

> **先说结论**：这个假设在梯度提升树上**被实测推翻了**，但在线性模型上被证实，而且赢的幅度是输的 10 倍。这个反差本身成了本项目最有价值的发现。完整数据见第六节。
>
> 下面先讲我们当初为什么这么想，因为理解假设才能理解它为什么错。
>
> **关于命名**：后续实测发现，那层「约束投影」**只在 0.06% 的行上真正改变了取值**
> —— 线性回归预测出来的值本来就几乎总是满足约束。所以 L3 的实质是
> **条件均值插补**（链式线性回归），「约束」二字名不副实。
> 本文后续一律以「条件均值插补」称呼它，把约束投影作为一个
> **试过但作用有限**的设计如实记录，而不是当作卖点。

普通的插补方法（比如用随机森林预测缺失值）只利用统计相关性。我们额外加入**发现 1 的硬约束**，让插补结果不能违反数据本身的物理规律。

| 情况 | 普通插补 | 我们的做法 |
|---|---|---|
| 屏幕时间缺失，社交和游戏都在 | 回归预测出一个值 | 回归预测后，**硬截断到 ≥ 社交 + 游戏** |
| 屏幕时间缺失，周末屏幕时间在 | 当作普通特征 | 走 +0.80 相关的**专用回归通道** |
| 社交时间缺失，屏幕和游戏都在 | 回归预测出一个值 | **硬截断到 ≤ 屏幕 − 游戏** |
| 游戏时间缺失，屏幕和社交都在 | 回归预测出一个值 | **硬截断到 ≤ 屏幕 − 社交** |
| 周末屏幕时间缺失，屏幕时间在 | 回归预测 | 按 1.33 的**比值分布**重建 |

一句话概括：**尊重数据硬约束的插补**。

举个例子：某人社交 3 小时、游戏 2 小时、屏幕时间缺失。普通插补可能给出 4.2 小时——但这是**不可能的**，因为 3 + 2 = 5 > 4.2。我们的方法会把它截断到至少 5 小时。这一步排除了大量不可能的取值，插补精度自然提高。

### 我们会做完整的对比

为了证明这个方法确实更好（而不是自说自话），我们跑一个 **4 × 4 的实验网格**：

| | glmnet | ranger | xgboost | lightgbm |
|---|---|---|---|---|
| ① 原生 NaN | — | — | ✓ | ✓ |
| ② 中位数填补 | ✓ | ✓ | ✓ | ✓ |
| ③ **约束条件插补** ★ | ✓ | ✓ | ✓ | ✓ |
| ④ **PMM 随机插补** | ✓ | ✓ | ✓ | ✓ |

（glmnet 和 ranger 不支持原生 NaN，所以第一行有两个空格。）

所有格子用**同一套交叉验证折叠**，所以 AUC 的差异只可能来自方法本身。

### 一个必须遵守的技术细节：防泄漏

**插补模型必须在每一折内部拟合，不能在全部训练数据上拟合一次再套用。**

否则验证集的信息会通过插补参数渗进训练过程，交叉验证分数会虚高。更麻烦的是：虚高的幅度随插补方法的复杂度递增，**这会系统性地偏袒当时我们看好的 ③ ④ 两条线**，让整个对比实验失去意义，最后得出"约束插补大胜"的假结论。

正确的循环结构已经写在 `R/06_model_TEMPLATE.R` 里，照抄即可。

> **事后看，这条纪律救了整个项目。** 正因为折内拟合从一开始就写死在模板里，第六节那个"插补越精细越差"的结论才站得住脚——否则我们大概率会看到一个被泄漏抬起来的假胜利，然后信以为真。

### 6.0 先说一件让人清醒的事：基础功课比我们全部的插补研究都值钱

我们最初的 xgboost 固定训练 600 轮 —— 那是拍脑袋定的数字，也没做过任何调参。
补上这两项基础功课之后：

| | CV AUC | 增益 |
|---|---|---|
| 固定 600 轮、默认参数（最初） | 0.95910 | — |
| 加早停（自动选轮数，均值 **1158**） | 0.96088 | **+0.00178** |
| 再加超参数搜索（`eta=0.05, depth=4`） | **0.96145** | **+0.00066** |
| **合计** | | **+0.00235** |

而下面 6.1 里**四条插补线之间的全部差距**是 0.00297（L1 对 L4）。

也就是说：两个我们从没认真想过的基础设置，收益几乎等于我们花最多篇幅研究的
那件事的全部。早停选出的轮数是硬编码值的近两倍 ——
**我们一直在用一个欠拟合的模型做所有对比**。

> **在花力气做精巧的方法创新之前，先确认基础设置没有把分数留在桌上。**

> 一个差点让整件事翻车的细节：xgboost 3.x 的 booster 是外部指针包装，
> `model$best_iteration` **恒为 NULL**，必须走 `xgb.attr()`，而且是 0-indexed。
> 第一版代码写了个静默兜底「取不到就用 100 轮」，结果 5 折全部用了 100 轮，
> AUC 掉到 0.94072，**而日志看起来完全正常**。
> 现在改成直接报错 —— 宁可炸掉，也不要让一个 API 变更伪装成一次正常的实验。

### 6.1 完整的 4×4 网格

| 插补线 | xgboost | lightgbm | ranger | glmnet |
|---|---|---|---|---|
| **L1** 不插补 | **0.96088** | **0.95983** | —（不支持 NA） | —（不支持 NA） |
| **L2** 中位数常数 | 0.96047 | 0.95975 | 0.93960 | 0.91780 |
| **L3** 条件均值 | 0.95951 | 0.95957 | **0.93980** | **0.92825** |
| **L4** PMM 随机 | 0.95791 | 0.95704 | 0.93581 | 0.91572 |

**按算法看，方向截然不同：**

```
能原生处理 NaN 的两个算法 —— 不插补最好，越精细越差
  xgboost    L1 0.96088 > L2 0.96047 > L3 0.95951 > L4 0.95791
  lightgbm   L1 0.95983 > L2 0.95975 > L3 0.95957 > L4 0.95704

不能处理 NaN、必须插补的两个算法 —— 条件均值插补反超
  ranger     L3 0.93980 > L2 0.93960 > L4 0.93581
  glmnet     L3 0.92825 > L2 0.91780 > L4 0.91572
```

**这不是一次巧合，是两个模型家族各自独立的复现。** 早期版本只有 xgboost 对 glmnet
一组证据，现在是 **2 对 2**，而且两侧内部的排序都完全一致。

glmnet 上 L3 相对 L2 的增益是 **+0.01045**（5/5 折同号，p<0.0001），
比它在 xgboost 上输掉的 0.00137 大将近一个数量级。

### 6.2 机制：关键在于「聚」还是「散」

我们先后提出并否定了两个解释：

1. ~~约束截断造成分布畸变~~ —— 实测约束**只在 0.06% 的行上触发**，插补后
   `other_screen` 均值 3.719 对真实值 3.709，分布几乎重合。约束投影实质上是个
   装饰品，这个数字可以用 `diagnose_constraints_L3()` 随时复现。
2. ~~回归估计向条件均值收缩~~ —— L4 用 PMM 从真实观测值里抽，完全不收缩，
   结果反而**最差**（四个算法上一致）。收缩不是主因。

能同时解释全部 14 个格子的，是第三个解释：**插补把缺失行在特征空间里「散开」的程度**。

- **L1** 把所有未知**聚在一起** —— GBDT 为每个分裂点学一个「遇到缺失往哪边走」
  的默认方向，一次决策管所有缺失样本
- **L2** 全部填同一个常数，本质上还是聚的（都堆在一个点）
- **L3** 按各自的条件均值散开
- **L4** 按真实分布随机散开，散得最开

散得越开，模型需要单独判断的行就越多，出错的机会也越多。
而 ranger 和 glmnet 没有「聚」这个选项 —— 每一行都必须拿自己的插补值去算分，
所以**猜得准**才是唯一重要的事。

> **能把「未知」聚起来统一处理的模型，聚比猜好；不能聚的模型，猜得准比猜得糙好。**

### 6.3 量级对比：模型类别比插补策略重要得多

xgboost **完全不插补**（0.96088）比**最好的** glmnet（0.92825）高出 **0.0326**，
是插补策略在 glmnet 内部造成差异（0.0105）的 3 倍、在 GBDT 内部造成差异
（0.0030）的 11 倍。

这一点在开工前不是显然的 —— 我们原本把大部分设计精力放在了插补上。

### 6.4 调参不改变结论（回答一个关键质疑）

「没调参就下 L1 > L2 > L3 > L4 的结论，万一换一组超参数就反转了呢？」
这是个合理的质疑，因为插补后的数据没有 NA，树的分裂行为完全不同，
最优深度本来就可能不一样。

我们用搜出来的最优参数（`eta=0.05, max_depth=4`）重跑四条插补线：

| 插补线 | 默认参数 | 最优参数 |
|---|---|---|
| L1 | 0.96078 | **0.96145** |
| L2 | — | 0.96061 |
| L3 | — | 0.95974 |
| L4 | — | 0.95792 |

**排序完全一致，结论不翻转。**

顺带一提，搜索结果显示**更浅的树更好**（depth 4 优于 6 和 8），
这与「标签几乎是少数几个特征的单调函数」（发现 5）是自洽的 ——
不需要很深的树去拟合复杂交互。

### 6.5 特征消融，以及据此做的两次删减

| 消融变体 | 特征数 | AUC | vs full | Cohen's d | 同号 | p |
|---|---|---|---|---|---|---|
| L1 全特征 | 31 | 0.96088 | — | — | — | — |
| L1 去掉 6 个派生特征 | 25 | 0.96099 | +0.00012 | 1.03 | 5/5 | 0.083 |
| **L3 去掉 6 个派生特征** | 25 | **0.95970** | **+0.00019** | **2.27** | **5/5** | **0.0071** |
| L1 去掉 12 个缺失指示 + n_missing | 18 | 0.96090 | +0.00003 | 0.38 | 3/5 | 0.448 |
| L1 去掉 gender/stress/impact | 28 | 0.96096 | +0.00009 | 1.05 | 1/5 | 0.079 |
| L1 去掉 age | 30 | 0.96089 | +0.00001 | 0.05 | 2/5 | 0.923 |
| **L1 去掉 `app_opens_per_day`** | 30 | **0.95383** | **−0.00705** | −18.99 | 5/5 | <0.0001 |
| **L1 去掉 `notifications_per_day`** | 30 | **0.95263** | **−0.00825** | −26.47 | 5/5 | <0.0001 |

三条结论：

**① 六个精心设计的派生特征全部无用，对 L3 甚至有害。**
它们基于发现 1、2、5、8 设计，删光之后 L1 分数不动（p=0.083），
而 **L3 反而变好且统计显著**（+0.00019，p=0.0071）。

这顺带回答了一个合理的怀疑：*插补制造的冗余变量会不会拖累 L3？*
我们确实测到了冗余 —— `weekend_ratio` 被其他特征解释的比例，
从观测行的 0.59 涨到插补行的 0.85；`other_screen` 的标准差被压缩 26%
（1.885 → 1.399，真实值 1.938）。**这个冗余确实有害，只是效应很小。**

> 值得注意的是：在早停之前（欠拟合的 600 轮模型上），这一项的 p 值是 0.373，
> 完全看不出来。**一个没调好的模型会掩盖真实的效应。**

**② EDA 判定的噪声特征，判对了三个。**
`gender` / `stress_level` / `academic_work_impact`（p=0.079，1/5 同号）、
12 个缺失指示（p=0.448）、`age`（p=0.923）—— 删掉全都毫无影响。

**③ 但漏判了两个，而且漏判的是最重要的。** 见发现 9。

#### 据此做的两次删减：31 特征 → 17 特征

**删减一：12 个缺失指示 + `n_missing`（13 列）。**
这组变量是为了检验"缺失位置本身是否携带信息"而造的**诊断变量**：
发现 6 已证明缺失为 MCAR，消融又给出 +0.00003（p=0.448），
置换重要性全部 ≤ 0.00001（其中 11 个为负）。诊断结论既已确定，
它们就没有理由继续留在特征集里。

**删减二：派生特征 `screen_social = 屏幕时间 + 社交时间`（1 列）。**
由发现 1 可知 social 本身即是 screen 的分量，二者相加等价于
`2×social + gaming + other` —— 社交被算了两遍。扫描 `screen + w×social`
显示最优权重是 w = 1.75 而非 1，说明权重 1 只是相加动作的副产物；
它与自身分量回归 **R² = 1.000000**，是精确线性组合，零新信息。
判定依据见 `R/16_screensocial_audit.R`。

删减后重新测量 L1 × xgboost（同一套冻结折叠、同一套参数）：

| 配置 | 特征数 | 交叉验证 AUC | 早停轮数 |
|---|---|---|---|
| 原 | 31 | 0.96088 ± 0.00125 | 1158 |
| **现** | **17** | **0.96107 ± 0.00121** | 1304 |

逐折差值 +0.00016 / +0.00048 / +0.00028 / −0.00012 / +0.00015，
均值 **+0.00019**，4/5 同号，Cohen's d = 0.86，**p = 0.128**。

n=5 的检验力不足以支持"显著改善"，因此这里只宣称一件事：
**删掉这十四列没有造成任何损失。**

**另一半的故事：在 glmnet 上，删减是轻微有害的。**

同样的删减在 L3 × glmnet 上重测：

| 配置 | 特征数 | 交叉验证 AUC |
|---|---|---|
| 原 | 31 | 0.92825 ± 0.00124 |
| 现 | 17 | 0.92814 ± 0.00123 |

差值 **−0.00010**，**5/5 折全部为负**，p = 0.0081。
量级只有万分之一，但方向高度一致，不是噪声。

这个符号翻转有明确机制，而且与本项目的核心发现是同一回事：

- **对树模型**，`screen_social` 只是一列冗余，缺失指示只是一列常数噪声；
  删掉它们减少了分裂时的干扰，所以略有改善。
- **对带惩罚的线性模型**，情况不同。glmnet 的系数受 L1/L2 惩罚约束，
  多一列 `screen + social` 意味着"同时给屏幕和社交加权"可以由**一个系数**
  承担，而不必分摊到两个系数上——这在惩罚下是更便宜的路径。
  删掉它并没有缩小可表示的函数空间（它本就在原有两列的张成里），
  但改变了收缩的几何形状。
- 同理，缺失指示对**不能原生表示"未知"的模型**是有信息的：
  插补之后，只有指示列还记得"这一行是猜出来的"。树模型自己会把未知聚在一起，
  用不上这个信息；线性模型没有这个选项。

**这不影响交付。** 最终提交是 GBDT 集成，glmnet 在集成里权重很低，
而 0.0001 的量级远小于集成本身的方差。但它值得写进报告：
**同一个"删掉无用特征"的动作，在两类模型上符号相反**——
这正是第 6.2 节「聚还是散」那条结论的又一个实例。


**为什么删这两组，却保留同样无效的五个派生特征和 gender / stress / age？**
因为三者性质不同：

| | 性质 | 处置 |
|---|---|---|
| 缺失指示 13 列 | 诊断变量，用完即弃 | 删 |
| `screen_social` | 定义上重复计数，且精确共线 | 删 |
| 其余 5 个派生特征 | 定义正当，只是恰好没用 | 留（`USE_DERIVED=0` 可关） |
| gender / stress / impact / age | 题目给定的原始特征 | 留 |

删除标准是"**这个量在概念上站得住吗**"，不是"它涨不涨分"——
四组的分数影响都在 ±0.0002 以内，本来也涨不了分。

#### 一处必须声明的口径差异

本节以上的消融表、6.1 的 4×4 网格、6.10 的集成结果与两次 Kaggle 提交，
**全部是在 31 特征配置下测得的**。删减之后只重跑了
L1 × xgboost 与 L3 × glmnet 两格（上表），以及特征重要性（见 `R/13_importance.R`）。
完整重跑 14 格网格约需 3 小时。依据消融给出的量级（±0.0002），
预期排序与全部结论不变；但在重跑完成之前，
本文档中的网格数字应按 **31 特征口径**理解。

两次新测量的产物存放在 `output/feat17/`（刻意与 `output/oof/` 分开，
以免被 `09_stats.R` 与 `run_tierb.R` 的 `^meta_grid_` 通配当成额外的网格格子）。

### 6.6 glmnet 的 alpha：我们的先验预测又错了

我们预期 alpha 偏小（偏 ridge）会更好，理由是本题共线性很强：
`other_screen` = 屏幕 − 社交 − 游戏 是原始列的**精确线性组合**，设计矩阵秩亏，
而 ridge 理论上更适合处理共线性。

| alpha | 含义 | AUC |
|---|---|---|
| 0 | 纯 ridge | **0.92414** ← 明显最差 |
| 0.25 | 偏 ridge | 0.92826 |
| 0.5 | 弹性网各半 | 0.92825 |
| 0.75 | 偏 lasso | 0.92826 |
| 1 | 纯 lasso | 0.92826 |

**纯 ridge 反而差 0.004，而 0.25 以上全部等价。** 我们原先固定的 0.5 是无害的 ——
但它当初确实没有依据，现在有了。

### 6.7 概率校准

评价指标是 AUC，只看排序，所以校准不影响成绩。但我们交的是**概率** ——
说一个人有 0.83 的概率成瘾，就该有 83% 的这类人真的成瘾。

| 模型 | AUC | Brier | ECE |
|---|---|---|---|
| L1_xgboost | 0.96086 | 0.07187 | 0.00709 |
| L3_xgboost | 0.95950 | 0.07316 | 0.00559 |
| **L4_xgboost** | 0.95791 | 0.07459 | **0.00491** |
| L3_glmnet | 0.92824 | 0.09883 | 0.01933 |
| L2_glmnet | 0.91780 | 0.10598 | 0.02276 |

（全预测基准率 0.7094 时 Brier = 0.2062，作为参照。）

全部模型校准良好（ECE < 0.023），GBDT 明显优于 glmnet。

**但有一个反直觉的现象**：`L4_xgboost` 的 AUC 最差，ECE 却**最低**（0.00491，
优于 L1 的 0.00709）。PMM 的随机插补保留了真实数据的分布形状，
产生了**校准更好但判别力更弱**的预测。
这两件事本来就可以分开 —— 一个模型可以「说得准」但「分不开」。

> **一个必须区分的点**：只有**单模型输出**才是概率。
> `07_ensemble.R` 里的 rank 平均和爬山法输出的是**秩**，
> 线性压到 (0,1) 之后形似概率，但不具备概率含义，谈它的校准没有意义。

### 6.8 为什么「假设被推翻」是个好结果

完整的推理链是这样的：

1. 假设条件均值插补会赢 → **实测在 GBDT 上输了**
2. 提出解释一（约束畸变）→ **测量后排除**（只触发 0.06%）
3. 提出解释二（均值收缩）→ **设计 L4 检验 → 被推翻**（PMM 不收缩却最差）
4. 提出解释三（聚 vs 散）→ 推出可证伪预测：**在不能「聚」的模型上，我们的方法应该反过来赢**
5. **验证：在 ranger 和 glmnet 上都赢了**，glmnet 上的幅度接近输的一个数量级

三次证伪 + 一次在两个模型家族上都成立的反向预测，每一步都有配对检验。
这比「我们试了一个方法，它成功了」结实得多，也更经得起追问。

### 6.9 必须声明的方法学限制

**① 特征选择的选择偏差。** 「哪些特征是噪声」的判断来自 EDA，
而 EDA 用了全部训练数据**和标签**，然后我们又在同一套折叠上评估删掉它们的效果。
严格做法应当把特征选择也放进折内。

我们没有这么做，但影响可控：**最终模型不做特征选择** ——
因为消融的结论恰恰是「筛了也不涨」。所以这个偏差只影响消融结果的解读，
不影响交付模型的分数。

**② 统计检验的样本量。** 5 折 CV 只给出 5 个配对差值，t 检验的正态性假设
无法验证。改用 Wilcoxon 符号秩检验**并不能解决** —— n=5 时它的双侧 p 值
下限是 2/2⁵ = 0.0625，永远达不到 0.05。

我们的做法是**增加样本量**：用 3 个不同的 fold seed 各做一次完整 5 折 CV，
把配对样本量提到 **n=15**，并一律同时报告 Cohen's d 与符号一致性，
不让 p 值单独承担结论。

**③ 子样本外推。** 对比实验在 20 万行上进行以控制算力，最终模型在全量 69 万行
上重训。两个规模下的排序一致性检查见 `R/run_tierb.R` 的输出。

---

### 6.10 最终验证：n=15 检验、全量重训、集成

#### 统计检验：把配对样本量提到 n=15

用 3 个不同的 fold seed 各做一次完整 5 折 CV：

| 对比 | 均值差 | Cohen's d | 同号 | p(t) | p(符号秩) | p(符号) |
|---|---|---|---|---|---|---|
| L1_xgboost − L2_xgboost | +0.00030 | 0.95 | 14/15 | 0.0024 | 0.0043 | 0.0010 |
| L2_xgboost − L3_xgboost | +0.00101 | 2.69 | 15/15 | <0.0001 | 0.0001 | 0.0001 |
| L1_xgboost − L3_xgboost | +0.00131 | 3.14 | 14/15 | <0.0001 | 0.0001 | 0.0010 |
| **L3_glmnet − L2_glmnet** | **+0.01044** | **21.16** | **15/15** | **<0.0001** | **0.0001** | **0.0001** |

**全部结论在 n=15 下依然成立。**

#### 顺带用数据证明了一件方法学的事

有人建议我们把配对 t 检验换成 Wilcoxon 符号秩检验，理由是 n=5 时 t 检验的
正态性假设无法验证。这个诊断是对的，但药方是错的 —— 我们把同一批比较在
n=5 和 n=15 下各跑一次，对照如下：

| 对比 | n=5 符号秩 p | n=15 符号秩 p |
|---|---|---|
| L1 − L2 (xgb) | **0.0625** | 0.0043 |
| L2 − L3 (xgb) | **0.0625** | 0.0001 |
| L1 − L3 (xgb) | **0.0625** | 0.0001 |
| L3 − L2 (glmnet) | **0.0625** | 0.0001 |

**四组比较在 n=5 时的符号秩 p 值一模一样，全部是 0.0625。**

其中 `L3_glmnet − L2_glmnet` 的 Cohen's d 高达 **32**、5/5 折同号 ——
一个大到不能再大的效应，符号秩检验依然只能报 0.0625。

原因是 n=5 时符号秩统计量只有 2⁵ = 32 种排列，双侧最小可能 p 值就是 2/32。
**这不是证据不足，是检验本身没有分辨率。** 换过去等于主动放弃全部统计功效。

正确的解法是增加样本量，而不是换一个在小样本下更保守的检验。

#### 全量重训：20 万上的结论能外推吗

| 模型 | Tier A（20 万） | Tier B（69 万） | 差值 |
|---|---|---|---|
| L1_xgboost | 0.96088 | **0.96454** | +0.00366 |
| L2_xgboost | 0.96047 | 0.96402 | +0.00354 |
| L1_lightgbm | 0.95983 | 0.96368 | +0.00385 |
| L2_lightgbm | 0.95975 | 0.96363 | +0.00388 |
| L3_lightgbm | 0.95957 | 0.96330 | +0.00373 |
| L3_ranger | 0.93980 | 0.94126 | +0.00146 |
| **L3_glmnet** | 0.92825 | **0.92778** | **−0.00047** |

**排序一致性 Spearman = 1.000，完全一致。** 20 万子样本上的全部结论都可以
外推到全量，我们的 Tier A / Tier B 两层设计是站得住的。

**但有一个值得注意的差异**：三个 GBDT 从 3.5 倍数据中获得了 +0.0037，
而 **glmnet 反而略微下降（−0.0005）**。

这说明 glmnet 受限的不是数据量，而是**模型容量** —— 它是线性的，
再多数据也拟合不出发现 5 那条陡峭的非线性曲线。ranger 介于两者之间（+0.0015）。

#### 集成：收益极小，而且原因清楚

| 集成方式 | CV AUC |
|---|---|
| 二层 logistic | 0.96450 |
| rank 平均 | 0.96140 |
| **爬山法** | **0.96477** ← 最优 |
| 最好的单模型（L1_xgboost） | 0.96453 |

**集成只带来 +0.00024。**

原因有两个，都值得讲：

**① 成员之间太像。** 七个成员里五个是 GBDT，它们之间的秩相关高达
0.94–0.996。集成的收益来自成员**犯不同的错**，而这五个模型基本在同一批
样本上犯同一批错。我们特意把 ranger（0.941）和 glmnet（0.928）拉进来
增加多样性 —— 最低秩相关因此从 0.991 降到 0.939，但仍然不够。

**② rank 平均反而比最好的单模型更差**（0.96140 对 0.96453）。
因为它给 glmnet 和 ranger 与 L1_xgboost 同等的权重，
而前两者分别低 0.037 和 0.023。爬山法能正确地给它们很低的权重，
所以是三种方式里唯一真正有提升的。

> 这是一个诚实但不好看的结果：**在一个存在明显最优单模型、
> 且候选高度同质的场景里，集成几乎没有价值。**
> 我们没有为了让集成好看而挑选成员或调整口径。

## 七、怎么复现我们的结果

### 环境要求

| | |
|---|---|
| R | 4.6.1 或更高 |
| RStudio | 任意近期版本 |
| 磁盘 | 约 2 GB（数据 + 中间产物） |
| 内存 | 建议 16 GB 以上 |

### 步骤

**第一步：获取代码**

```bash
git clone https://github.com/XIRANZHANG-X/smartphone-addiction-prediction.git
```

**第二步：装包**

在 RStudio 里打开 `smartphone-addiction-prediction.Rproj`，然后：

```r
source("R/00_setup.R")
```

这个脚本会用 `renv` 按照 `renv.lock` 里记录的**精确版本**安装所有依赖包，保证你装的和我们用的完全一致。

**第三步：下载数据**

数据文件约 68 MB，且 Kaggle 竞赛数据不宜公开再分发，因此**没有放进 git 仓库**。请从 Kaggle 竞赛页面下载以下三个文件，放进 `data/raw/` 目录：

```
data/raw/train.csv
data/raw/test.csv
data/raw/sample_submission.csv
```

**第四步：跑通全流程**

最省事的方式是一条命令跑完全部实验（每一步都会跳过已有产物，中断后重跑会续上）：

```bash
Rscript R/run_pipeline.R
```

它依次执行：14 格实验网格 → 特征消融 → 超参数搜索 → alpha 敏感性 → 概率校准 → 重复交叉验证 → Tier B 全量重训 → 集成 → 生成提交文件 → 汇总结果表。

想手动分步跑：

```r
source("R/01_load.R")       # 读数据
source("R/03_features.R")   # 特征工程
source("R/04_folds.R")      # 折叠契约（固定 seed，可复现）
# 单个模型格子：Rscript R/06_model_L1_xgboost.R
source("R/07_ensemble.R")   # 集成
source("R/08_submit.R")     # 生成提交文件
```

**全部实验数字**汇总在 [output/results.md](../output/results.md)，由 `R/11_report.R` 自动生成 —— 文档里不手抄数字，改了实验重跑一次即可刷新。

生成的提交文件在 `submissions/` 目录下。

### 随机性说明

所有涉及随机的步骤都设了固定 seed，**同样的输入必然得到同样的输出**。如果你跑出来的 AUC 和我们报告的不一致，说明环境有差异，请先检查 `renv::status()`。

## 八、常见问题

**Q：为什么不用 Python？**
课程要求用 R。

**Q：为什么不试试神经网络？**
特征只有 12 维，且发现 5 表明信号结构非常清晰（近乎单调），梯度提升树已经贴近上限。上神经网络只会增加复杂度而不增加分数，这个判断写在设计文档的"明确不做"一节里。

**Q：既然不插补效果最好，为什么还要写四条插补线？**
因为"不插补最好"这个结论本身就是靠这四条线跑出来的——没有对照组，它只是一句猜测。而且这个结论只对能原生处理缺失的模型成立：glmnet 和 ranger 必须插补，对它们来说插补质量差一个数量级。四条线缺一不可。

**Q：约束条件插补失败了，那这个项目的创新点还剩什么？**
剩下的比原来的更硬：一个**交互效应**——同一个方法在两类模型上结论完全相反，且我们用配对检验、机制排除、和一次成功的反向预测把它钉死了。原来的假设如果直接成功，我们只能说"我们的方法好用"；现在我们能说清楚"插补什么时候有用、什么时候有害、以及为什么"。

**Q：为什么对比实验只用 200,000 行而不是全部 691,369 行？**
`ranger`（随机森林）在全量数据上跑一折就要二三十分钟，14 个格子全量跑不现实。所以对比实验统一在分层抽样的 20 万行上做——**因为大家用的是同一个子集和同一套折叠，横向比较依然严格成立**。只有最终进入集成的候选模型才在全量数据上重训。这一点在报告里会明确说明。

**Q：`folds.rds` 为什么不能重新生成？**
它决定了每一行属于哪一折。一旦重新生成，之前所有人跑出来的分数就不再可比，全组的实验结果作废。它是固定 seed 生成的，进了 git，直接用就好。
