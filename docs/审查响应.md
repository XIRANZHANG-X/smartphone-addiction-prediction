## 一句话总结

审查提出的 **最重要的一条是对的，而且被严重低估了**：加早停带来 **+0.00178** 的提升，
比我们花了大量篇幅研究的四条插补线之间的全部差距（0.00292）的一半还多。

同时有 **一条建议不能照做**：把配对 t 检验换成 Wilcoxon 符号秩检验会让情况更糟，
真正的解法是增加样本量。详见 1.4。

**最终账目**：早停 +0.00178，调参 +0.00066，合计 **+0.00244** —— 而四条插补线之间的全部差距是 0.00297。**基础功课的收益几乎等于整个插补研究。**

另外，新加的诊断在第一次运行时就抓到两个真 bug 和一句假注释，见文末。

## 一、严重问题

### 1.1 无早停 ✅ 已修复并验证

**审查意见成立，而且影响远超预期。**

原先所有 xgboost 固定 `nrounds = 600`。加早停后（训练折内再切 20% 做监控，
定下轮数后在训练折全量上重训）：

| | CV AUC | 实际轮数 |
|---|---|---|
| 固定 600 轮 | 0.95910 ± 0.00130 | 600（拍脑袋） |
| **早停** | **0.96088 ± 0.00125** | 1080 / 1083 / 1249 / 1216 / 1160（均值 **1158**） |

**增益 +0.00178。** 早停选出的轮数是硬编码值的近两倍 —— 原来的模型是**欠拟合**的，
而我们一直以为 600 是个保守但安全的选择。

实现在 `R/lib_models.R` 的 `make_xgb()` / `make_lgb()`。

> **一个顺带抓到的坑**：xgboost 3.x 的 booster 是外部指针包装，
> `names(model)` 只有 `"ptr"`，`model$best_iteration` **恒为 NULL**，
> 必须走 `xgb.attr(model, "best_iteration")`，而且它是 **0-indexed**。
>
> 我第一版写了个静默兜底 `if (is.null(best)) best <- 100L`，结果 5 折全部
> 用了 100 轮，AUC 掉到 0.94072 —— 而日志看起来一切正常。
> 现在改成直接报错：宁可炸掉，也不要让 API 变更伪装成一次正常实验。

### 1.2 无超参数调优 ✅ 已完成

**审查意见成立**，尤其是它指出的第二层风险：
「没有调参的情况下得出 L1 > L2 > L3 > L4，只有在所有方法对超参数同等敏感时才成立」。

`R/10_tune.R` 做两件事：

1. **两阶段粗搜**（学习率 × 树深 → 正则化），共 18 组参数，3 折 20 万行
2. **稳健性检查** —— 用搜出来的最优参数**重跑四条插补线**，看排序是否翻转

**结果**：搜索了 18 组参数，最优是 `eta=0.05, max_depth=4`。

| | AUC |
|---|---|
| 默认 `eta=0.05, depth=6` | 0.96078 |
| 最优 `eta=0.05, depth=4` | **0.96145** |
| 调参增益 | **+0.00066** |

**稳健性检查回答了审查最深的那个担忧**：用最优参数重跑四条插补线，排序仍然是 **L1 (0.96145) > L2 (0.96061) > L3 (0.95974) > L4 (0.95792)**，与默认参数下**完全一致，结论不翻转**。

顺带的发现：更浅的树更好（depth 4 优于 6 和 8），这与「标签几乎是少数几个特征的单调函数」自洽 —— 不需要深树去拟合复杂交互。

### 1.3 折内无验证集 ✅ 已随 1.1 解决

早停所需的内部验证集从**训练折内部**再切 20%，外层验证折从头到尾不参与
任何模型选择，构成真正的嵌套交叉验证。定下轮数后在训练折全量上重训，
不浪费那 20% 的数据。

### 1.4 配对 t 检验的样本量 ✅ 已修复，但**不按审查建议的方式**

**问题诊断成立**：n=5 时 t 检验的正态性假设无法验证。

**但开出的药方会让情况更糟。** 审查建议改用 Wilcoxon 符号秩检验，
而 n=5 时符号秩统计量只有 2⁵ = 32 种排列，**双侧最小可能 p 值是 2/32 = 0.0625**。
也就是说即使 5 折全部同号、效应量再大，也永远达不到 p < 0.05。
换过去等于主动放弃全部统计功效。

**真正的解法是增加配对样本量**，不是换一个在小样本下更保守的检验。
`R/09_repeated_cv.R` 用 3 个不同的 fold seed 各做一次完整 5 折 CV，
把配对样本量从 **n=5 提到 n=15**。

同时 `R/09_stats.R` 现在一律同时报：

- **Cohen's d**（效应量，不随样本量变化）
- **符号一致性**（k/n，不对分布作任何假设）
- t 检验、符号秩检验、符号检验三个 p 值，并标注各自的 n

不让 p 值单独承担结论。审查建议的 Wilcoxon 仍然计算并报出，
但注明它在小 n 时的分辨率下限。

> **重要**：重复 CV 的结果**只用于统计检验**，不进网格对比表。
> 网格表里的数字仍然来自冻结的 `folds.rds`，那是全组共享的唯一口径。

### 1.5 特征选择泄漏 📝 文档处理 + 一个审查漏掉的关键点

**审查对偏差存在性的判断成立**，我们原先的自我辩护确实不够。

但有一点审查没有指出，而它让这个问题在实践上是 **moot** 的：

> **最终模型不做特征选择。** 因为消融的结论恰恰是「筛了也不涨」——
> 删掉 EDA 判定的噪声特征后 AUC 反而掉 0.007。

所以这个偏差只影响**消融结果的解读**，不影响交付模型的分数。
我们没有基于泄漏的选择去构建最终模型。

审查提到的另一点非常对，我们已写进 [项目说明.md 发现 9](项目说明.md)：
`notifications_per_day` 从「噪声」被翻案为最重要特征这件事，
**本身就是在全体数据上做特征选择很危险的证据** —— 如果当初直接删了，
就永远不会发现它的重要性。

## 二、中等问题

### 2.1 L3 的「约束」名不副实 📝 已在文档中降级

约束投影实测**只在 0.06% 的行上触发**，L3 实质上是链式线性回归插补。

已做：
- `R/05_impute_L3.R` 新增 `diagnose_constraints_L3()`，让这个 0.06% 随时可复现，
  而不是靠一句注释
- 文档中一律以「**条件均值插补**」描述其实质，「约束投影」作为一个
  **试过但作用有限**的设计写在方法节
- 幻灯片中不以「约束插补」作为卖点，避免答辩时被追问

### 2.2 L4 硬编码 seed ✅ 已修复（真 bug）

原代码在 `apply_imputer_L4` 里写死 `seed = 1000L`，导致 5 折的 missRanger
用了**完全相同的随机种子**，折与折之间的插补结果存在非预期的相关性。

改为在 `fit_imputer_L4` 里从框架的随机流派生：

```r
list(line = "L4", donor = ..., seed = sample.int(.Machine$integer.max, 1L))
```

框架每折调用前都会 `set.seed(SEED + k)`，所以各折 seed 不同（折间独立），
整体流程仍然完全可复现。

### 2.3 派生特征已确认无效但未删除 ✅ 已加开关

框架新增 `USE_DERIVED` 配置（也可通过环境变量 `USE_DERIVED=0` 覆盖）。
默认保留，因为「我们试过 6 个精心设计的派生特征，全部无效」本身是报告
里的一条阴性结论，删掉就没有证据了。需要精简 pipeline 时一个变量即可关闭。

### 2.4 代码大量重复 ✅ 已重构

6 个模型文件每个 210 行、其中 200 行完全相同 —— 审查说得对，
这意味着改一个 bug 要改 6 处，而且没有任何机制保证它们真的相同。

现在拆成两层：

| 文件 | 职责 |
|---|---|
| `R/06_framework.R` | 全部框架逻辑：数据加载、Tier 选择、防泄漏的 CV 循环、存盘 |
| `R/lib_models.R` | 模型工厂 `make_xgb()` / `make_lgb()` / `make_ranger()` / `make_glmnet()`，早停只写一遍 |
| `R/06_model_*.R` | **27 行**，只有配置和一行 `fit_predict <- make_xgb()` |

从 210 行降到 27 行，而且加早停这种改动只需改 `lib_models.R` 一处，14 个格子同时生效。

> **重构时踩的坑**：第一版 `run_grid.R` 用 `sys.source(f, envir = new.env())` 做隔离，
> 14 个格子全部秒退报「未定义 MODEL_NAME」。原因是模型文件里的
> `source("R/06_framework.R")` 用默认 `source()`，在**全局环境**求值，
> 看不到塞进 `new.env()` 的配置。改成**每个格子开独立子进程** ——
> 这本来就是组员实际使用的方式（`Rscript R/06_model_X.R`），隔离彻底。

### 2.5 glmnet 的 alpha = 0.5 缺乏依据 ✅ 已完成（我们的先验预测错了）

`R/09_alpha_scan.R` 扫 `alpha ∈ {0, 0.25, 0.5, 0.75, 1}`。

先验预期是 alpha 偏小更好，理由写在脚本注释里：本题特征数量很少，不需要
大规模特征选择，但共线性很强（`other_screen` = 屏幕 − 社交 − 游戏 是原始列的
**精确线性组合**，设计矩阵秩亏），而 ridge 比 lasso 更适合处理共线性。
**结果推翻了我们的先验**：

| alpha | 含义 | AUC |
|---|---|---|
| 0 | 纯 ridge | **0.92414** ← 明显最差 |
| 0.25 | 偏 ridge | 0.92826 |
| 0.5 | 弹性网各半 | 0.92825 |
| 0.75 | 偏 lasso | 0.92826 |
| 1 | 纯 lasso | 0.92826 |

纯 ridge 反而差 0.004，而 0.25 以上全部等价。原先固定的 0.5 **是无害的，但当初确实没有依据 —— 现在有了**。

### 2.6 无概率校准评估 ✅ 已完成

`R/09_calibration.R` 计算 Brier score、ECE（期望校准误差）和可靠性曲线。

**但要指出审查没有区分的一点**：只有**单模型输出**才是概率。
`07_ensemble.R` 里的 rank 平均和爬山法输出的是**秩**，被线性压到 (0,1)
之后形似概率，但不具备概率含义 —— 谈它的校准没有意义。
脚本只评估单模型，并在报告中明确这个区分。

**结果**：全部 14 个模型校准良好（ECE < 0.023），GBDT 明显优于 glmnet。

**但有一个反直觉的现象值得写进报告**：`L4_xgboost` 的 AUC 最差（0.95791），ECE 却**最低**（0.00491，优于 L1 的 0.00709）。PMM 的随机插补保留了真实数据的分布形状，产生了**校准更好但判别力更弱**的预测 —— 「说得准」和「分得开」本来就是两件事。

## 三、轻微问题

### 3.1 `renv.lock` 缺失 ✅ 已生成

`R/make_lockfile.R`，记录 60+ 个包（含全部传递依赖）的精确版本。

> **为什么不直接跑 `renv::init()`**：它会在项目根目录创建 `.Rprofile`，
> 让**之后每一次** R 启动都自动激活一个项目本地的包库 —— 而那个库一开始是空的。
> 后果是正在跑的后台实验突然找不到 xgboost，组员 clone 下来第一次打开也满屏报错。
> 对一个 10 人协作、随时有长任务在跑的项目，这个副作用不可接受。
>
> 改为在**临时目录**里建一次性 renv 项目生成 lockfile，只把那一个文件拷回来。
> 脚本结尾会校验项目目录未被污染。

### 3.2 集成与提交脚本从未运行 ✅ 已重写并跑通

重写时提前修掉一个会致命的性能问题：爬山法原本用 `pROC::roc` 在 55 万行上
反复算 AUC（30 步 × N 模型 × 5 折 ≈ 900 次调用，每次约 1 秒）。
改用秩公式 `AUC = (正例秩和 − n₁(n₁+1)/2) / (n₁n₀)`，只需一次排序，
快两个数量级，结果与 `pROC` 完全一致。

同时加了逐个模型的形状校验（长度、NA、test 文件是否存在），
不合格的跳过并报警，不让它污染集成。

**跑通后又抓到两个问题：**

**① 我在自己写的 `fast_auc` 里重犯了整数溢出。** `sum(y == 1)` 返回**整型**
490,474，全量上 `n1 * n0 ≈ 9.85e10` 超出 32 位上限直接变 NA ——
七个模型的 AUC 全部变成 NA，集成静默失败。这和 `04_folds.R` 里踩过的
是同一类坑，说明**只要在 R 里写整数乘法就该先想一想量级**。

**② 候选选择只按 AUC 取前 N，选出了五个几乎相同的模型。**
实测它们之间秩相关高达 **0.991~0.996**。集成的收益来自成员犯不同的错，
五个雷同的模型平均起来提升极其有限。改为「每个算法家族各取最好的一个，
再按 AUC 补足」，把 ranger 和 glmnet 拉进来，最低秩相关降到 0.939。

**最终集成只提升 +0.00024**（0.96453 → 0.96477）。这是个诚实但不好看的
结果，我们如实记录 —— 在存在明显最优单模型、候选又高度同质的场景里，
集成本来就没什么价值。

### 3.3 消融脚本代码重复 ✅ 已修复

`09_ablation.R` 和 `09_ablation_decompose.R` 各自重新实现了一遍 xgboost 逻辑 ——
主模型改参数它们不会跟着改，而消融的全部意义就在于「除被消融的特征外一切相同」。

两个脚本已合并为一个 `R/09_ablation.R`，统一从 `R/lib_models.R` 取模型工厂，
与 `06_model_*.R` 用的是同一份代码、同样的早停。

### 3.4 L3 收敛诊断缺失 ✅ 已补

`apply_imputer_L3` 现在记录每轮插补值相对上一轮的平均绝对变化量
（按各列标准差归一化），存进 `attr(dt, "l3_delta_trace")`。
最后一轮变化超过 1% 个标准差就发 warning 提示调大 `N_ITER_L3`。

### 3.5 类别特征编码方式 ✅ 已加独热选项

`.to_matrix()` 新增 `onehot` 参数。**glmnet 路径强制独热**（线性模型把
无序类别当有序数值是实打实的错误）；树模型保持整数编码 ——
这三个类别特征已被消融证明是纯噪声（p=0.183），实际影响为零，
不值得为此增加 6 列。

## 四、审查中「做得好的地方」的自我核对

审查给 `折内插补防泄漏` 打了 ★★★★★，这一条我们认同并且要强调：

**正是这个设计让「插补越精细越差」的结论站得住。** 如果当初图省事在全量
训练数据上拟合一次插补器，虚高幅度会随插补复杂度递增，
我们大概率会看到一个被泄漏抬起来的**假胜利**，然后信以为真地写进报告。

这也是为什么新框架把这条纪律写死在 `06_framework.R` 里而不是模板注释里 ——
注释可以被忽略，框架不能。

## 六、审查提出但我们不采纳的

**唯一一条：1.4 改用 Wilcoxon 符号秩检验。**

理由已在 1.4 详述：n=5 时该检验的双侧 p 值下限是 0.0625，永远达不到 0.05，
换过去等于放弃全部统计功效。我们采纳了它背后的**问题诊断**（n=5 不稳健），
但用增加样本量而非更换检验来解决。

审查建议里提到的 5×2 CV 配对 t 检验（Dietterich 1998）和
corrected resampled t-test（Nadeau & Bengio 2003）是更专业的方案，
我们采用的重复 5 折是它们的简化版本 —— 在教学项目的算力预算下更实际，
且同样解决了样本量问题。这个取舍在报告中会说明。
