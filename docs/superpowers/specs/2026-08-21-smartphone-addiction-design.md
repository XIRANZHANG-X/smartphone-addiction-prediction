## 0. 实测修订（2026-08-21 当日）

本文档记录的是**开工前的设计判断**，其中两条已被实测推翻。原文保留不改，因为"我们当初怎么想、为什么错"本身是报告的重要材料。以下是需要读者知道的更正：

| 原文主张 | 位置 | 实测结果 |
|---|---|---|
| 约束条件插补是全项目的 novelty，能带来分数增量 | §3.5、§4 | **推翻**。在 xgboost 上它比完全不插补低 0.00105（5/5 折同号，t=7.14，p=0.0020），是同类中最差 |
| L3 是「唯一不可放弃」的线，因为它是核心创新 | §4 | **理由变了，结论不变**。L3 仍不可放弃，但因为它在 glmnet 上是决定性最优（+0.01065，p<0.0001）——正是这个**方向相反**构成了真正的发现 |
| 约束投影会显著改善插补质量 | §3.5 | **推翻**。约束实测只在 **0.06%** 的行上触发，实质上是无操作。L3 当前等同于链式线性回归插补 |
| L4 = 多重插补 m=5 + 模型平均 | §3.5 | **已重新设计**。原实现取 m 份插补的平均，恰好抹平 PMM 保住的随机性，等于退化成 L3，无法检验任何东西。改为单次 PMM 随机插补 |
| `screen_social` 是「近似充分统计量」 | §3.3 | **命名不成立**。由 F1 可知 social 本身是 screen 的分量，二者相加等价于 `2×social + gaming + other`，社交被算了两遍。作为单变量打分器它确实有效（AUC 0.912 对 screen 单独的 0.889），但扫描 `screen + w×social` 发现最优 `w = 1.75` 而非 1 —— 权重 1 只是相加动作的副产物。模型中置换重要性仅 0.00096，与自身分量回归 **R² = 1.000000**（零新信息，对 glmnet 造成秩亏）。见 `R/16_screensocial_audit.R` |

**替代结论**（有完整配对检验支撑）：

> 插补的价值完全取决于下游模型能否自行表示「未知」。GBDT 的原生缺失处理会把所有未知**聚在一起**用一个学到的默认方向统一处理；显式插补把它们**散开**到各自的估计值上，散得越开，需要单独判断的行越多，出错机会越多。而线性模型没有「聚」这个选项，因此猜得准才重要。

完整数据与推理链见 [项目说明.md 第六节](../../项目说明.md)，当前进度见 [进度.md](../../进度.md)。

**未被推翻、且事后证明关键的设计**：§3.1.1 的折内插补纪律。正因为它从一开始就写死在模板里，上面那个"越复杂越差"的结论才站得住——否则会看到一个被泄漏抬起来的假胜利。

## 2. 数据实测结论（全量扫描，非抽样）

### 2.1 缺失情况

| 列 | 缺失率 | 列 | 缺失率 |
|---|---|---|---|
| `age` | 4.18% | `notifications_per_day` | 9.78% |
| `daily_screen_time_hours` | 13.86% | `app_opens_per_day` | 11.67% |
| `social_media_hours` | 19.38% | `weekend_screen_time` | 16.21% |
| `gaming_hours` | 18.34% | `gender` | 4.20% |
| `work_study_hours` | 7.45% | `stress_level` | 7.98% |
| `sleep_hours` | 6.43% | `academic_work_impact` | 6.40% |

完整行仅 269,185（38.94%），**61.06% 的行至少缺一个特征**。

### 2.2 关键发现

**F1 — 硬结构约束（100% 成立）**

```
daily_screen_time_hours >= social_media_hours + gaming_hours
成立 451,246 / 451,246 行 = 100.00%
```

屏幕时间可分解为 社交 + 游戏 + 其他，其中 `other_screen = screen - social - gaming` 均值 3.71、标准差 1.94。这是**可用于插补的确定性边界**，也是本项目自创方法的立足点。

**F2 — 周末屏幕时间是冗余代理**

`weekend / screen` 比值：均值 1.3303，标准差 0.4984（n=517,906）；相关系数 **+0.80**。二者极少同时缺失，可互相重建。

**F3 — 相关结构**

```
screen ↔ weekend  +0.80      screen ↔ social   +0.60
screen ↔ work     +0.53      screen ↔ gaming   +0.43
social ↔ gaming   +0.09      ← 两个近乎独立的分量
age / notif / opens / sleep ↔ 一切  ≈ 0
```

**F4 — 三个特征是纯噪声**

`stress_level` × `academic_work_impact` 全部 6 种组合下正例率完全平坦：

| 组合 | 低分段（screen+social<6） | 中分段（8–10） |
|---|---|---|
| High / No | 0.2035 | 0.6685 |
| High / Yes | 0.2085 | 0.6678 |
| Low / No | 0.2073 | 0.6735 |
| Low / Yes | 0.2133 | 0.6665 |
| Medium / No | 0.2162 | 0.6809 |
| Medium / Yes | 0.2201 | 0.6712 |

`notifications_per_day` 同样平坦（全区间 0.69–0.73）。`gender` 三类近乎均匀分布且与目标无关。

**F5 — 标签近乎是 (screen, social, gaming, work) 的确定性函数**

complete-case 上 `screen + social` 分箱正例率单调 **0.14 → 1.00**，无任何反复：

```
 0–1: 0.176      5: 0.255      9: 0.758     13: 0.998
 2–3: 0.165      6: 0.318     10: 0.888     15: 1.000
   4: 0.196      7: 0.417     11: 0.963    17+: 1.000
                 8: 0.582     12: 0.990
```

**F6 — 缺失机制为 MCAR，缺失指示无信息量**

各列 missing/present 的目标率差全部 ≤ 0.0042（最大者 `age` +0.0042、`sleep` +0.0042）；按缺失个数分组，正例率在 0.696–0.719 间无趋势。**Kaggle 常用的「缺失指示特征」在本题无效**——这是可用数据证明的阴性结论，价值高于正面结果。

**F7 — `work_study_hours` 的 Simpson 悖论**

| 视角 | 结果 |
|---|---|
| 边际 | 0.6113 → 0.9299（正向） |
| 条件于低 screen+social | 0.2454 → 0.0421（**负向**） |

成因是 `screen ↔ work` 相关 +0.53。边际上的正相关完全由屏幕时间的混淆效应造成。

**F8 — 「空闲时间」假设不成立**

`24 - sleep - work - screen` 均值 7.19、标准差 3.78，且 1.84% 为负——不是硬约束，只能作软特征。

### 2.3 问题定性

**这不是建模题，是缺失数据题。**

标签在完整数据上近乎确定；难度全部来自 61% 的行有缺失。理论最优预测是 `E[y | 观测到的特征子集]`，需要对缺失分量做条件边缘化。而特征间相关性高达 0.4–0.8，意味着**观测特征中蕴含大量关于缺失特征的信息**。

- 均值/中位数填补 → 破坏信号
- GBDT 原生 NaN → 仅走缺失分支，不利用相关结构
- **利用相关结构 + 硬约束的插补 → 本方案的技术空间**

名次差异将出现在小数点后第三位，而这一位由缺失处理决定。

## 3. 技术方案

### 3.1 折叠契约（架构核心）

`R/04_folds.R` 一次性生成 `folds.rds`：固定 seed，对 691,369 行做**按目标分层的 5 折**。

> **该文件生成后任何人不得重新生成，进 git，当常量使用。**

所有模型线遵守同一接口：

```
输入： features_raw.rds   全组共享，含 NA 的原始特征矩阵（03_features.R 产出）
       folds.rds          全组共享，冻结的折叠标签
       features_L<k>.rds  本线专属，由 05_impute_L<k>.R 从 features_raw 产出

输出（两个层级，见 3.6）：
  Tier A 对比实验  output/oof/oof_grid_<名字>.rds    长度 200,000
                   （无 test 产物，Tier A 不参与集成）
  Tier B 集成候选  output/oof/oof_<名字>.rds         长度 691,369
                   output/test/test_<名字>.rds       长度 296,302
```

**`features_raw.rds` 只含不依赖插补的特征**（原始列 + 缺失指示 + `n_missing`）。所有比值/差值型派生特征（`other_screen`、`weekend_ratio` 等）在**插补之后**由各线自行计算——因为它们的取值依赖于插补结果，放在插补前会引入 NA 传播。

三个直接后果：

1. **任意两人的分数可直接比较**——同折同数据，AUC 差异只来自方法本身。这正是 rubric 中「方法间技术对比」要求的实体。
2. **集成层零耦合**——`07_ensemble.R` 只读取目录下所有 `oof_*.rds` 作为二层特征。加人加模型无需修改任何已有代码。
3. **git 零冲突**——每人只写自己的 `R/06_model_<名字>.R`，文件级隔离。战力不均的组尤其关键：某人交不出来，删掉其文件即可，主线毫发无伤。

### 3.1.1 泄漏控制（强制约束）

**插补模型必须在每一折内部拟合，不得在全训练集上拟合一次后套用。**

在全量训练集上拟合插补模型，等于让验证折的信息通过插补参数渗入训练——CV 分数会虚高，且虚高幅度随插补方法的复杂度递增。这恰好会**系统性地偏袒本项目主推的 ③、④ 两条线**，使整个对比实验失去意义。

因此每条线的执行顺序固定为：

```
for k in 1..5:
    在 folds != k 上拟合插补模型
    用它变换 folds != k（训练）与 folds == k（验证）
    训练模型 -> 预测 folds == k -> 写入 OOF 第 k 折位置
最终 test 预测：在全训练集上重新拟合插补 + 模型，再变换 test
```

第 2 条对照线（中位数填补）同理——中位数必须在折内计算。这是一条**验收标准**，`06_model_*.R` 的模板会把这个循环结构固定下来，组员只需填模型部分，从结构上杜绝写错。

### 3.3 特征工程（`03_features.R`，全组唯一真源）

按 3.1 的划分，特征分两批产出。

**批一 · `features_raw.rds`（插补前，全组共享）**

```r
12 个原始列（保留 NA）
n_missing            # 每行缺失个数
is_na_<col>          # 各列缺失指示，共 12 个
```

缺失指示是**故意保留**的：已量化确认缺失为 MCAR（F6），因此「缺失指示无效」是一个可用数据说话的阴性结论，纳入消融研究。这批特征不依赖插补，因此可以安全地在折外一次性计算。

**批二 · 派生特征（插补后，各线在折内自行计算）**

```r
other_screen  = screen - social - gaming      # F1：保证 >=0 的第三分量
weekend_ratio = weekend / screen              # F2：约 1.33
social_share  = social / screen
gaming_share  = gaming / screen
free_frac     = screen / (24 - sleep - work)  # F8：软特征
screen_social = screen + social               # F5：近似充分统计量
```

这批**必须放在插补之后**：它们全部是比值或差值，任一分量为 NA 就会传播成 NA，插补前计算等于白算。`03_features.R` 导出一个 `derive_features()` 函数供四条线复用，保证口径一致——**函数共享，调用时机各线自定**。

对 ① 原生 NaN 线：跳过插补，直接在含 NA 的数据上调 `derive_features()`，派生列自然带 NA，交由 xgboost / lightgbm 原生处理。这是该线的定义特征，不是缺陷。

### 3.4 4×4 实验网格

| | glmnet | ranger | xgboost | lightgbm |
|---|---|---|---|---|
| **① 原生 NaN** | — | — | ✓ | ✓ |
| **② 中位数填补 + 缺失指示** | ✓ | ✓ | ✓ | ✓ |
| **③ 约束条件插补 ★** | ✓ | ✓ | ✓ | ✓ |
| **④ 多重插补 m=5 + 模型平均** | ✓ | ✓ | ✓ | ✓ |

共 14 个有效格子（glmnet / ranger 不支持原生 NaN，该空格本身是一条讲解点）。

### 3.5 约束条件插补（★ 自创方法）

直接利用 F1、F2、F3：

| 场景 | 处理 |
|---|---|
| `screen` 缺失，`social`+`gaming` 在 | 回归预测后**硬截断到 ≥ social + gaming** |
| `screen` 缺失，`weekend` 在 | 走 +0.80 相关的回归通道 |
| `social` 缺失，`screen`+`gaming` 在 | **硬截断到 ≤ screen − gaming** |
| `gaming` 缺失，`screen`+`social` 在 | **硬截断到 ≤ screen − social** |
| `weekend` 缺失，`screen` 在 | 按比值分布重建 |

一句话概括：**尊重数据硬约束的插补**。具备明确物理意义，且直接源于本组的 EDA 发现。

多重插补（④）使用 `missRanger`（基于 ranger 的链式随机森林插补），而非 `mice`——在 691k 行规模上 `mice` 不可行。`mice` 在子样本上跑一次作为方法学对照并在报告中说明取舍。

### 3.6 算力预算与子采样决策

`ranger` 在 691k×25 上单折需二三十分钟，14 个格子全量不可行。因此：

> **网格对比实验在分层子采样 200k 上进行**（同折同数据，横向严格可比）；**仅进入最终集成的候选在全量 691k 上重训**。

具体落地为两个层级：

| | Tier A · 对比实验 | Tier B · 集成候选 |
|---|---|---|
| 数据量 | 200,000（分层子采样） | 691,369（全量） |
| 覆盖 | 全部 14 个格子 | Tier A 中 AUC 前 5~6 名 |
| 折叠 | **复用 `folds.rds` 的同一折标签**，不重新划分 | 同上 |
| OOF 产物 | `oof_grid_<名字>.rds`，长度 200,000 | `oof_<名字>.rds`，长度 691,369 |
| test 产物 | 无 | `test_<名字>.rds`，长度 296,302 |
| 用途 | 报告中的方法对比表与热力图 | 输入 `07_ensemble.R` |

子样本由 `04_folds.R` 一并生成 `subsample_200k.rds`（存行索引），与 `folds.rds` 同样冻结。**关键点：子样本继承原折标签而非重新划分**，否则 Tier A 与 Tier B 的分数不可比，跨层级的结论会失效。

**只有 Tier B 参与集成**——用 200k 的 OOF 去训二层模型，再套到全量上，会造成尺度与分布错配。

这是主动的设计决策，报告中明写「对比实验在 200k 子集上进行以控制变量与算力，最终模型在全量上重训」。省下的时间用于多做两轮调参。

### 3.7 验证协议

- 5 折分层 CV，报告 **mean AUC ± sd**（跨折标准差是稳定性证据，进对比表）
- Kaggle LB 仅用于**交叉验证 CV 的可信度**：提交 top-2 候选，确认 CV 与 LB 同向
- **最终提交按 CV 选定，不按 Public LB 选定**——防 Public LB 过拟合
- 每次提交记入 `submissions/log.csv`：时间、方法、CV、LB

### 3.8 集成

三种方式横向对比（又一个对比点）：

1. 二层 logistic 回归（在 OOF 上训练）
2. rank 平均
3. 爬山法搜索权重

## 8. 明确不做（YAGNI）

- **逆向工程数据生成公式**——已评估并放弃，风险收益比不佳
- 神经网络 / TabNet 等——本题特征仅 12 维且信号结构清晰，GBDT 已接近上限，徒增复杂度
- `catboost`——不在 CRAN，需 GitHub 二进制安装，风险高于收益
- 深度超参搜索（多轮贝叶斯优化）——收益在小数点后第四位，不如把时间投入插补研究
- 复杂的 git 分支保护 / PR 流程——文件级隔离已消除冲突，10 人直推 main 即可
